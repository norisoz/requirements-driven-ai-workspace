# requirements-analysis

対象工程: P04, P05

## 実行手順

1. 現在工程・成果物・出典・ユーザー確認結果を読み、実際に参照したもののみ使用する。

2. 入力済みの確認済み事項と、PROPOSED/UNKNOWN/CONFLICTEDを分離する。

3. 条件付き項目の真偽がunknownなら、その条件確認を最優先する。

4. 不足と重大問題を整理し、ユーザーには優先度の高い1〜3問を聞く。

5. ファイルを作成・変更する前に、`AGENTS.md` の最優先ルールに従い7項目の作業計画を提示し、人間の作業実行承認を得る。承認後、回答を出典付きでJSON正本に反映し、`scripts/render_markdown.py` でMarkdown版を自動生成・整合検証する。

6. 完了判定: テーラリング規則（T01〜T08）適合、必須確認済み、条件解消、重大問題・未解決情報不足なし、根拠整合、JSON↔MD整合、利用可能チャネルによる実際の人間承認。未実施の機械検証を実施済みと呼ばない。

7. 承認済み版は上書きせず、新版（`supersedes_version` 付き）と差分を作成する。

## 工程別の確認観点

### P04 要求分析

目的: 重複・矛盾を整理し、人間が優先度と実現方針を決める。

確認項目（R=必須, C=条件付き, O=任意）:

- **R** `classification`：要求を業務、システム、データ、AI、ルール、評価、運用等に分類してください。

- **R** `duplicates_and_conflicts`：重複・潜在的矛盾・解決状況を列挙してください。「なし」も判断根拠が必要です。

- **R** `priorities`：各要求の優先度と人間の判断根拠は何ですか。

- **R** `feasibility`：実現可能性、制約、未解決の技術課題を列挙してください。

- **R** `risks`：要求を実現する際のリスクと対応方針は何ですか。

- **R** `realization_options`：人、業務、ルール、システム、AIなどの選択肢と比較理由は何ですか。

- **R** `selected_approach`：人間が採用した実現方針と選定理由は何ですか。

- **C** `ai_data_requirements` / 条件: `uses_ai=true`：AI利用範囲、データ条件、不確実性と評価要求を明示してください。

- **C** `sensitive_data_controls` / 条件: `handles_sensitive_data=true`：データ保護・アクセス統制上の要求を示してください。

- **O** `simplification_decisions`：所与の条件（既存手順・承認・規則・データ項目）を見直し、簡素化・廃止した判断内容を記録してください。（ハンドブック1.4節）

- **C/O** `ai_social_impact`（`ENHANCED` かつ `uses_ai=true` で必須）：AIの社会的受容性・倫理的影響（影響を受ける人、不利益・バイアス・差別、説明可能性、異議申立て手順、AI出力の明示、人間関与）を評価してください。（ハンドブック5.5節 表22）

- **C/O** `data_supply_chain`（`ENHANCED` かつ `uses_ai=true` で必須）：データ供給チェーン（出自/Provenance、利用目的整合、権利処理、多様性・代表性・バイアス、アノテーション基準、加工履歴、保存・削除）を示してください。（ハンドブック8.4節 表29〜30）

- **C** `global_local_requirements` / 条件: `is_global=true`：グローバル共通要件・リージョン要件・ローカル要件・例外要件の区分、データ越境、用語集、法制度・商習慣の差異を整理してください。（ハンドブック第4章 表15〜16）

### ハンドブック準拠の確認観点（P04）
- **AI非前提・代替手段とライフサイクルコスト比較（8.5節）**: 最初からAI利用を前提とせず、ルールベース・既存システム・SaaS・人による業務等と比較し、運用後のデータ整備・監視・モデル更新・人間確認コストを含めて適用範囲を見極める。
- **AI要求の11項目（5.2節 表18）**: AI利用目的、利用範囲、禁止範囲、入力データ、出力要件、人間の関与、評価指標、監視要件、更新要件、証跡要件、インシデント対応。
- **ビルディングブロック単位の分解と選定観点（10.2〜10.6節 表35〜38）**: 新規開発/既存活用/OSS/商用/SaaS/外部API/AIサービスの組み合わせを検討し、相互運用性・データ管理・ベンダーロックイン・監査可能性を確認する。

出力: `AGENTS.md` の「期待する毎ターンの応答（ユーザー向け表示規約）」に従い、内部変数名・スクリプト名・挨拶・否定前置きを省いた端正なビジネス表現で、現在工程・充足している情報（表）・不足している情報（表）・最優先の質問（最大3件、可能なら `ask_question` 等の選択式UI）を提示する。内容確認・承認依頼時はJSONを読ませず成果物内容を表形式で提示し、検証結果も「〜についての確認（指摘○件）」の日本語表で示す。

### P05 要求仕様化

目的: 人と機械の両方が参照でき、評価可能な仕様を作る。

確認項目（R=必須, C=条件付き, O=任意）:

- **R** `specifications`：各要求を識別子付きで明確に仕様化してください。

- **R** `scope_and_conditions`：各仕様の対象、前提条件、境界条件を示してください。

- **R** `acceptance_criteria`：何を満たせば受け入れられるか、観測可能な条件を示してください。

- **R** `verification_methods`：各仕様をどのように検証しますか。

- **R** `exception_handling`：例外や失敗時にどう処理するかを示してください。

- **C** `ai_evaluation_requirements` / 条件: `uses_ai=true`：AIの入力、出力、介入、評価、更新条件を明示してください。

- **O** `output_format`：文書、表、BPMN等の指定はありますか。

- **C/O** `ai_uncertainty_failsafe`（`ENHANCED` かつ `uses_ai=true` で必須）：AIの不確実性・迷った時の振る舞い（確信度低下、入力不十分、OOD想定外入力、根拠不明、ハルシネーション疑義、フェイルセーフ、人間エスカレーション）を仕様化してください。（ハンドブック5.3節 表19〜20）

- **C/O** `prompt_management_spec`（`ENHANCED` かつ `uses_ai=true` で必須）：業務利用するプロンプト（目的・役割・入力・制約・出力形式・評価基準・確認事項・根拠）と参照データ・レビュー手順・変更履歴・承認・評価のセット管理仕様を示してください。（ハンドブック5.4節 表21）

### ハンドブック準拠の確認観点（P05）
- **要求仕様の11観点（8.6節 表31）**: 目的、対象、入力、処理、出力、制約、例外、評価、監視、変更、証跡。
- **要件の品質特性（2.4節）**: 必要性、一意性、実現可能性、検証可能性、無矛盾性、適切な粒度、上位目的・下位実装へのトレース可能性。要求管理台帳（`requirements/ledger.json`）の `SPECIFICATION` とID紐付けし二重管理を避ける。

出力: `AGENTS.md` の「期待する毎ターンの応答（ユーザー向け表示規約）」に従い、内部変数名・スクリプト名・挨拶・否定前置きを省いた端正なビジネス表現で、現在工程・充足している情報（表）・不足している情報（表）・最優先の質問（最大3件、可能なら `ask_question` 等の選択式UI）を提示する。内容確認・承認依頼時はJSONを読ませず成果物内容を表形式で提示し、検証結果も「〜についての確認（指摘○件）」の日本語表で示す。

## 実行補足（ワークスペースルート基準）
参照ファイル: `shared/phase_definitions.json`、`shared/tailoring_profiles.json`、`shared/schemas/phases/Pxx.schema.json`。
- **`SCRIPT_VERIFIED` モード**（Python実行可能時）：`python3 scripts/resolve_tailoring.py ...`、`python3 scripts/render_markdown.py --render --verify ...`、`python3 scripts/validate_gate.py --markdown ...`（環境により `python`）で機械検証し、誤りがあれば戻す。
- **`STANDARD_SHELL_AUDIT` モード**（プログラム実行不可の社内PC）：`scripts/*.py` のロジックと `shared/*.json` を参照して全項目をチェックリスト検証し、ハッシュ・参照ID・差分はOS標準コマンド（macOS: `shasum`/`grep`/`diff`、Windows: `certutil`/`findstr`/`fc`）で実測したうえで人間レビューへ回す（機械実行済みと偽装しない）。
永続保存は差分を提示し、承認済みファイルを上書きしない。
