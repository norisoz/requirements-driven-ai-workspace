# model-traceability

対象工程: P06

## 実行手順

1. 現在工程・成果物・出典・ユーザー確認結果を読み、実際に参照したもののみ使用する。

2. 入力済みの確認済み事項と、PROPOSED/UNKNOWN/CONFLICTEDを分離する。

3. 条件付き項目の真偽がunknownなら、その条件確認を最優先する。

4. 不足と重大問題を整理し、ユーザーには優先度の高い1〜3問を聞く。

5. ファイルを作成・変更する前に、`AGENTS.md` の最優先ルールに従い7項目の作業計画を提示し、人間の作業実行承認を得る。承認後、回答を出典付きでJSON正本に反映し、`scripts/render_markdown.py` でMarkdown版を自動生成・整合検証する。

6. 完了判定: テーラリング規則（T01〜T08）適合、必須確認済み、条件解消、重大問題・未解決情報不足なし、根拠整合、JSON↔MD整合、利用可能チャネルによる実際の人間承認。未実施の機械検証を実施済みと呼ばない。

7. 承認済み版は上書きせず、新版（`supersedes_version` 付き）と差分を作成する。

## 工程別の確認観点

### P06 モデリング

目的: 詳細化はリスク相応とし、重要な関係の可視化と要求整合を確認する。

確認項目（R=必須, C=条件付き, O=任意）:

- **R** `model_scope`：何をどの粒度でモデル化しますか。

- **R** `models`：業務・ルール・データ・構成・評価の関係を表すモデルを列挙してください。

- **R** `nodes_and_relationships`：主要な要素、関係、依存を一覧化してください。

- **R** `requirement_links`：モデル要素と要求IDの対応を示してください。

- **R** `model_review`：関係者によるモデル確認結果を示してください。

- **C** `ai_model_boundary` / 条件: `uses_ai=true`：AIに委ねる範囲・人間の介入ポイントを図示してください。

- **C** `compliance_mapping` / 条件: `has_external_obligations=true`：法令・標準とモデル要素の関係を示してください。

### ハンドブック準拠の確認観点（P06）
- **Human Readable から Machine Understandable へ（9.2節 表32）**: 人間が理解しやすい図・表・業務フロー・用語集に加え、ID・メタデータ・データモデル・ルールモデル・トレーサビリティで機械処理可能性を高める。
- **段階的モデリングと代表的手法（9.3節 表33・9.6節）**: 業務フロー/BPMN、UML、SysML、ArchiMate、ER図/データモデル、オントロジー、ルール表、リスクマトリクス、トレーサビリティマトリクスをリスク相応に使い分ける。
- **軽量な形式手法（9.7節 表34）**: 安全性・セキュリティ・業務ルール・状態遷移・AI利用制限・フェイルセーフ・コンプライアンス等の重要制約は、状態遷移図・決定表・ルール表・制約一覧で厳密化・検証可能にする。
- **社内ルールの構造化（第14章）**: 正本の明確化、文書ID・版・所管部門・改定履歴、義務/禁止/承認/例外の区別、AI参照可否の区別を行い、Markdown/XML/Akoma Ntoso型構造やReqIF連携を考慮する。

出力: `AGENTS.md` の「期待する毎ターンの応答（ユーザー向け表示規約）」に従い、内部変数名・スクリプト名・挨拶・否定前置きを省いた端正なビジネス表現で、現在工程・充足している情報（表）・不足している情報（表）・最優先の質問（最大3件、可能なら `ask_question` 等の選択式UI）を提示する。内容確認・承認依頼時はJSONを読ませず成果物内容を表形式で提示し、検証結果も「〜についての確認（指摘○件）」の日本語表で示す。

## 出典との関係

工程名称と観点はIPAハンドブック第7章7.2、第6章、第16章を参照。フィールド名、分岐、ゲートは独自設計でありIPAが指定した機械規格ではない。

## 禁止事項

資料未参照の根拠を捏造しない。関係者の実際の合意・承認を代替しない。勝手に既存のベースラインを変更しない。

## 実行補足（ワークスペースルート基準）
参照ファイル: `shared/phase_definitions.json`、`shared/tailoring_profiles.json`、`shared/schemas/phases/Pxx.schema.json`。
- **`SCRIPT_VERIFIED` モード**（Python実行可能時）：`python3 scripts/resolve_tailoring.py ...`、`python3 scripts/render_markdown.py --render --verify ...`、`python3 scripts/validate_gate.py --markdown ...`（環境により `python`）で機械検証し、誤りがあれば戻す。
- **`STANDARD_SHELL_AUDIT` モード**（プログラム実行不可の社内PC）：`scripts/*.py` のロジックと `shared/*.json` を参照して全項目をチェックリスト検証し、ハッシュ・参照ID・差分はOS標準コマンド（macOS: `shasum`/`grep`/`diff`、Windows: `certutil`/`findstr`/`fc`）で実測したうえで人間レビューへ回す（機械実行済みと偽装しない）。
永続保存は差分を提示し、承認済みファイルを上書きしない。
