# AI要求管理・プロンプト運用ワークスペース（v2 設計書・運用ガイド）

本ドキュメントは、持続的なプロンプト更新・Antigravity標準のSkills活用・人間にとっての分かりやすさを両立させるための新フォルダ構成（`v2/`）の設計書です。

> **現行フォルダとの関係**
> ワークスペースルート配下の現行フォルダ・既存ファイルは一切変更せずそのまま温存します。新構成はすべて `v2/` 配下に独立して構築しています（本フォルダ単体を独立リポジトリとして GitHub 公開・展開可能です）。

---

## 0. 初期設定・クイックスタート（はじめて利用する方へ）

### 前提環境
- **AIエージェント環境**: Google Antigravity（または `AGENTS.md` / `.agents/skills/` に対応したエージェント環境）
- **Python 3（任意）**: 案件自動生成ツール（`tools/new_project.py`）および検証ツールを使用する場合のみ（標準ライブラリ中心で動作）。Python実行不可の社内PC等では手動コピー手順で運用可能です。
- **対応OS**: macOS / Windows 共通

### ステップ1：リポジトリを取得してワークスペースを開く
```bash
git clone https://github.com/norisoz/requirements-driven-ai-workspace.git
```
取得したフォルダ（本 `README.md` が直下にあるルート）をそのまま Antigravity のワークスペースとして開きます。
ルート直下の `AGENTS.md` と `.agents/skills/` が自動で認識されます。

### ステップ2：動作確認（任意・Python利用可能環境）
```bash
python3 tools/new_project.py --list
```
「該当する既存案件はありません。」と表示されれば初期状態として正常です（Windows環境では `python3` を `python` に読み替えてください）。

### ステップ3：最初の案件を開始する
1. 今回AIに読み込ませたい資料（PDF・Word・Excel・メモ・画像等）があれば、`inputs/` フォルダへ配置する。
2. Antigravity のチャットで「`inputs/` の資料をもとに提案書を作成したい」等と依頼する。
3. AIが選択式UIで「成果物仕様」「案件名・タスク種別」「参照範囲」「`inputs/` 資料の移動承認」を確認するため、選択して進める。
4. 承認後、`projects/<YYYYMMDD_案件名>/` が生成され、資料が移動して `inputs/` は空へ戻る。

### ステップ4：自分専用スキルを追加したい場合（任意）
チーム共通ではなく自分専用のスキルを追加する場合は、リポジトリ外の各PC標準パスへ配置します（他者やGit履歴に影響しません）。
- 配置先：`~/.gemini/config/skills/<スキル名>/SKILL.md`

### Git運用・機密情報保護の注意
- `.gitignore` により、`inputs/` に投入した実資料（`README.md` 除く）および `projects/` 配下の個別案件フォルダ（`_template/` 除く）は **Gitの追跡対象から自動除外** されます。
- 共通プロンプト（`tasks/`）やチーム共通スキル（`.agents/skills/`）を更新して共有する際は、事前に `git status` を確認し、業務データや機密情報が含まれていないことを確認してからコミットしてください。

## 1. 設計コンセプト（5つの基本原則）

1. **コア工程の不変運用（`core/` ＋ `.agents/skills/` のコア6スキル）**
   - 作業前承認、目的確認、品質検証、版管理などの核となる工程・ルールは原則として変更しません（管理者による計画改訂のみ）。
2. **タスク別の明確な編集箇所と使用Skillsの明示（`tasks/`）**
   - 業務タスクごとに独立フォルダを設け、中身を統一3ファイル（`prompt.md` / `template.md` / `checklist.md`）に限定します。各 `prompt.md` 内で「どのスキルをどの工程で使うか」を明示します。
3. **Antigravity標準Skillsへの統合と知見の即時スキル化（`.agents/skills/` ＋ `~/.gemini/config/skills/`）**
   - チーム共通スキルは Antigravity 自動認識パス（`v2/.agents/skills/`）へ統合し、個人独自スキルは各ユーザーPCの `~/.gemini/config/skills/` を利用します。
   - SNSのTipsや添削画像・NG例を見つけた際は、メタスキル `skill-curator` を使い、対象タスク・使用工程を選択式UIで人間承認のうえ即座にスキル化・反映できます。
4. **依頼ごとの案件インスタンス化（`projects/`）**
   - ユーザーからの依頼（案件）ごとに専用フォルダを複製・初期化し、その時点のタスクプロンプト控え・工程記録・最終納品物・出典資料を1か所に隔離管理します。
5. **作成経緯の透明性確保〔試験運用〕（`projects/<案件>/reports/`）**
   - 「どのような要求を受けて第一版を作成し、その後どのような指摘を受けてどう修正したか」を時系列で記録・出力できる透明性レポート用フォルダを各案件内に設けます。

## 2. フォルダ構成（全体像）

```text
v2/
├── README.md                          # 本書（全体構成・編集ガイド・運用手順）
│
├── .agents/
│   └── skills/                        # 【Antigravity標準Skills】自動認識されるスキル群
│       ├── README.md                  # コア6スキル（変更禁止）と共通拡張スキル一覧
│       ├── mission-intake/            # [コア] 工程1：目的・ミッション確認
│       ├── stakeholder-elicitation/   # [コア] 工程2〜3：関係者・要求獲得
│       ├── requirements-analysis/     # [コア] 工程4〜5：要求分析・仕様化
│       ├── model-traceability/        # [コア] 工程6：モデル化・紐付け
│       ├── validation-baseline/       # [コア] 工程7〜8：品質レビュー・基準版確定
│       ├── realization-lifecycle/     # [コア] 工程9〜12：実現引継ぎ・運用・変更・廃止
│       ├── skill-curator/             # [共通] Tips・NG例のスキル化＆タスク反映メタスキル
│       └── slide-anti-patterns/       # [共通] AIスライドで避けるべき要素集（01_slides用）
│
├── core/                              # 【基本変更しない】コア規範・スキーマ・定義・雛形
│   ├── AGENTS.md                      # 常時適用される共通行動規範（選択式UI承認含む）
│   ├── schemas/                       # 形式検証用スキーマ定義
│   ├── templates/                     # 共通テンプレート（成果物・透明性レポート雛形）
│   └── profiles/                      # 工程定義・管理水準ルール定義
│
├── tasks/                             # 【微調整する場所】タスク別プロンプト（初期7種別）
│   ├── 01_slides/                     # 資料作成（スライド・図解など）
│   ├── 02_proposals/                  # 提案書・企画書作成
│   ├── 03_programming/                # プログラミング・開発支援
│   ├── 04_research/                   # 調査・分析レポート作成
│   ├── 05_policies/                   # 規程・方針・手順書作成
│   ├── 06_minutes_notices/            # 議事録・要約・社内通知作成
│   └── 07_vuln_triage/                # 脆弱性脅威度調査
│       ├── prompt.md                  #   └ タスク固有指示＋使用するSkills（工程別）
│       ├── template.md                #   └ 成果物の標準構成・出力雛形
│       └── checklist.md               #   └ 提出前レビュー観点・確認リスト
│
├── inputs/                            # 【資料の受付トレイ】人間が今回読ませたい資料を置く場所
│   └── README.md                      #   └ 案件作成・再開時に案件内 inputs/ へ移動され空に戻る
│
├── projects/                          # 【依頼ごとの作業場】案件インスタンス格納先
│   ├── _template/                     # 新規案件作成時に複製するテンプレート一式
│   └── <YYYYMMDD_案件名>/             # 依頼ごとに生成される独立フォルダ
│       ├── project.json               # 案件属性・参照範囲設定・曖昧検索用要約・進捗状態
│       ├── prompt_snapshot.md         # 開始時点のコア参照＋タスクプロンプト控え
│       ├── inputs/                    # 共通トレイから移動された本案件専用の入力資料
│       ├── artifacts/                 # 工程ごとの中間・確定成果物（版管理）
│       ├── deliverables/              # 最終納品物（.pptx / .md / コード等）
│       ├── sources/                   # 参照資料・出典台帳
│       └── reports/                   # 【試験運用】透明性レポート出力先
│           └── transparency_report.md #   └ 初期要求→第一版→指摘→修正履歴レポート
│
└── tools/                             # 【運用補助】インスタンス化・検証ツール
    ├── new_project.py                 # 依頼ごとに projects/<案件>/ を自動生成
    └── validators/                    # 形式・整合性・Office構造チェックツール群
```

> **個人独自スキルの配置先**: 各ユーザー個人のスキルは、リポジトリ外の各PC標準パス `~/.gemini/config/skills/<スキル名>/SKILL.md` へ配置します（他者に影響せず、Antigravityが自動認識します）。

## 3. 早見表：何をしたい時にどこを編集するか

| やりたいこと | 編集・操作する場所 | コアへの影響 |
|---|---|---|
| タスクの書き方・トーン・使用Skillsを微調整したい | `v2/tasks/<該当タスク>/prompt.md` | なし |
| 成果物の見出し構成やフォーマットを変えたい | `v2/tasks/<該当タスク>/template.md` | なし |
| レビュー時の確認項目を追加・見直したい | `v2/tasks/<該当タスク>/checklist.md` | なし |
| SNSのTipsやNG例を即座にスキル化してタスクへ反映したい | `skill-curator` スキルを起動（画像・メモを投入し選択式UIで承認） | なし |
| 自分専用のスキルを追加して試したい | `~/.gemini/config/skills/<スキル名>/SKILL.md` | なし |
| チーム全員に展開したいスキルを登録したい | `v2/.agents/skills/<スキル名>/SKILL.md` | なし |
| 今回AIに読ませたい資料を渡して新規または再開作業を始めたい | `v2/inputs/` に資料を配置し、AIの選択式UI確認を経て案件内 `inputs/` へ自動移動 | なし |
| 新しい依頼・案件を開始して成果物を整理したい | `v2/projects/<YYYYMMDD_案件名>/` を新規生成 | なし |
| 案件の要求〜第一版〜指摘・修正の経緯を確認・共有したい | `v2/projects/<YYYYMMDD_案件名>/reports/transparency_report.md` | なし |
| 承認ルールや全社共通の安全制約を見直したい（管理者のみ） | `v2/core/AGENTS.md` | あり（要レビュー・承認） |

## 4. プロンプト・スキルの適用優先順位と衝突防止ルール

1. **第1優先：`v2/core/` および `v2/.agents/skills/` のコア6スキル**（絶対制約・承認統制・基本工程）
2. **第2優先：`v2/tasks/<選択タスク>/`**（タスク固有指針・工程別使用Skills・雛形・チェック観点）
3. **第3優先：`v2/.agents/skills/` のチーム共通拡張スキル**（`skill-curator`、`slide-anti-patterns` 等）
4. **第4優先：`~/.gemini/config/skills/`**（各ユーザーPCの個人独自スキル）

## 5. 依頼ごとの案件インスタンス化・資料移動・再開運用

### 新規案件の開始（`v2/inputs/` から資料を移動して空に戻す）
```bash
python3 v2/tools/new_project.py \
  --name "20261124_脆弱性調査案件" \
  --task 07_vuln_triage \
  --user <ユーザー名> \
  --summary "CVE-XXXXの脅威度調査" \
  --keywords "脆弱性,CVE" \
  --move-inputs
```
※ 元ファイルを残したい場合は `--move-inputs` の代わりに `--copy-inputs` を使用します。

### 中断・終了案件の検索と再開（曖昧検索＋追加資料取り込み）
```bash
# 曖昧なキーワードで既存案件を検索
python3 v2/tools/new_project.py --list --query "脆弱性"

# 選択した既存案件へ v2/inputs/ の追加資料を移動（同名時は日時付きで保全）
python3 v2/tools/new_project.py --attach "20261124_脆弱性調査案件" --move-inputs
```

### 手動コピー（プログラム実行不可の社内PC等）
1. `v2/projects/_template/` を丸ごとコピーし、`v2/projects/<YYYYMMDD_案件名>/` にリネームする。
2. `v2/inputs/` に置いた資料を `v2/projects/<YYYYMMDD_案件名>/inputs/` へ移動する。
3. `v2/tasks/<該当タスク>/prompt.md` の内容を、コピー先フォルダ内の `prompt_snapshot.md` へ転記する。

## 6. 透明性レポートの運用設計（試験運用）

各案件の `reports/transparency_report.md` に以下を時系列で記録します。
1. **案件・初回要求サマリー**（初回依頼内容、確定した目的・成果物仕様・管理水準）
2. **第一版の作成記録**（版番号、作成日時、判断根拠、参照出典、使用プロンプト控え）
3. **レビュー指摘と修正履歴**（回次・日時・指摘者・指摘内容・修正箇所・修正内容・反映版）
4. **現行版の承認状況と申し送り事項**

| 第5章 5.4（表21・脚注18 コンテキストエンジニアリング） | プロンプトは一回限りの文章ではなく要求仕様の一部であり、参照データ・出力形式・レビュー手順・利用制限・ログとセットで共有・評価・更新・版管理する | `v2/tasks/<タスク>/` でのプロンプト・出力雛形・チェックリストの一体管理、開始時点の控え（`prompt_snapshot.md`）、`v2/inputs/` によるコンテキスト（参照資料）制御 |
| 第6章 6.1〜6.4・6.7・6.8 | AIはヒアリング・文書化・過不足確認を支援する道具であり、AIの出力は「候補」として扱う。目的・優先度・リスク受容・承認は人間が責任を持ち、AIが承認済み成果物を直接上書きしない | `v2/core/AGENTS.md` における作業実行前の7項目承認、承認済み版の不変原則、選択式UIによる人間判断・承認の徹底 |
| 第7章 7.1〜7.2 | 目的・ミッションの確認（工程1）から廃止・移行（工程12）までのプロセスを、一方向ではなく反復・循環するライフサイクルとして扱う | `v2/.agents/skills/` に配置したコア6スキル（12工程の骨格）と、原則変更しないコア運用 |

| 第9章 9.2・第14章 14.2 | 人間が理解・合意できる表現（Human Readable / Understandable）と、AI・ツールが処理できる軽量な構造化（Markdown・JSON・メタデータ・スキーマ）の両立 | `project.json`・JSON Schema・検証ツール群と、Markdownテンプレート・表形式提示・YAMLメタデータ付き `SKILL.md` の併用 |
| 第10章 10.1〜10.4 | 全体を巨大な一枚岩にせず、役割・入出力・責任範囲が明確な再利用可能部品（ビルディングブロック）に分離し、変更容易性と技術更新への強さを高める | 不変の `core/`、タスク別に微調整可能な `tasks/`、Antigravity標準で着脱可能な `.agents/skills/`＋個人スキル、依頼単位で独立する `projects/<案件>/` |
| 第13章 13.2（図26 社内ルールの階層） | 社内規則→ガイドライン→マニュアル・手順書→チェックリストの階層を明確にし、AIがどの階層のルールに基づいて動作しているかを明示する | 4層優先順位（第1優先：コア規範 ＞ 第2優先：タスク指針 ＞ 第3優先：チーム共通スキル ＞ 第4優先：個人スキル）の明文化 |

> **独自設計との境界について**
> 上記の思想・工程の考え方は同ハンドブックに基づいていますが、具体的なフォルダ構成（`v2/`）、Antigravity標準Skills連携、`skill-curator` メタスキル、`v2/inputs/` 自動移動および曖昧検索による案件再開スクリプト（`v2/tools/new_project.py`）、ならびに透明性レポート（`reports/transparency_report.md`）の書式自体は、ハンドブックの思想を日々の業務へ落とし込むための本ワークスペース独自設計です。
